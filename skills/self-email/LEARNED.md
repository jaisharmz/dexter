# Learned — self-email

Corrections this skill has earned in use. Read before running it; these override
`SKILL.md`. Protocol: `kernel/skill-learning.md`.
- **2026-09-30** — Gmail enforces Trusted Types, so assigning innerHTML throws. Keep the email as a string: gzip and base64 the rendered HTML (65 KB becomes 7 KB, so the tool call stays small), decode it in the page with DecompressionStream('gzip'), and hand the string straight to the synthetic paste's DataTransfer (2026-09-30).
- **2026-09-30** — A compose window opened by the #inbox?compose=new URL can come up minimized when the tab is not in front, and typing then goes nowhere. Click the New Message bar to expand it, then fill To and Subject, and read both back by script before Send (2026-09-30).
- **2026-09-30** — Opening the email to confirm it arrived marks it read, and an inbox sorted with Unread first then hides it below the fold. After checking, press Mark as unread so it waits where the operator looks first (2026-09-30).
- **2026-09-30** — deslop.py reads the title from a '# ' line, so the rendered --text version always reports 'no title'. Prefix it with '# <title>' in a scratch copy before running the gate. An essay-review email uses the renderer's 'blocks' sections (label, note, text) so the operator can reply to each draft by its label.
- **2026-10-05** — When the operator asks for another draft of something they review by email, send it as a reply on the same thread, with the Gmail connector's reply tool, to their own address only and with no cc or bcc. This overrides SKILL.md's no-reply-on-a-thread rule for the operator's own self-email threads only. render.py --text leaves out the footer, so add it to the plain-text body by hand.
- **2026-10-09** — Start the morning email's dated list with today itself: read today's events on the primary, [CLAUDE] Confirmed and [CLAUDE] Suggested calendars and list each call or offered window. The Oct 9 email's This week list began on Sunday and left out two of that day's calls.
- **2026-10-09** — A Gmail-connector send_message wraps every link in a google.com/url redirect stamped to expire about 24 hours after sending, auto-links bare URLs and compacts inline styles, so the delivered email is never byte-exact; check what went out with get_message on the raw message, and for links he will use days later prefer a Chrome compose paste
- **2026-10-11** — The end-of-run summary email folds in the previous few summary emails (overnight runs, the everything email, rolling roles) into one cohesive current picture: dedupe, update each item's status, drop what is done. Fewer words; lists, tables and visual structure carry it. Length is fine, missing anything is not, because the operator reads only this email.
- **2026-10-11** — Gmail clips a message over about 102 KB behind 'View entire message', which hides the end of a long report. Measure the rendered HTML before sending and keep it under about 95 KB: render.py now sets cell type on the table, not on every cell (119 KB became 94 KB for the Oct 11 report); past that, cut words, not rows.
- **2026-10-11** — Audit every number in a results email against the data before sending, not after: one summary went out with a speed and cost ratio that counted refusals as lookups, and a later audit forced a correction reply. When a report backs the email, take the email's numbers from the audited report.
- **2026-10-11** — A long report must fit one send_message call: the Oct 11 report rendered to 95 KB of HTML, about 48K tokens to emit, too big for one call. Compact markup fixed it: cellpadding on the table, bare <td> and <th>, a light zebra background on every second row instead of per-cell borders, and no per-table font-family. That gave 61 KB of HTML and a 69 KB message. Upload a PDF the email needs to Drive with Chrome's file_upload (copy it into the working folder first) and link it; hand-copying base64 risks a corrupt file.
- **2026-10-11** — The Gmail connector's send filters the HTML: it drops the background shorthand, overflow-wrap and the <wbr> tag, and keeps background-color, the bgcolor attribute, word-break, cellpadding and valign (no-recipient drafts read back with get_draft, Oct 11). Every chip it sent had come out bare, and so had the Oct 11 report's shaded rows, so render.py writes fills as background-color and wraps long paths with a word-break span. Before relying on a new style property, test it the same way: a draft with no recipient, get_draft, then trash_message.
